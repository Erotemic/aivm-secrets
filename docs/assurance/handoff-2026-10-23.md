## 2. Claim delta

New or changed theorems (all compile; no new axioms in the extraction, which
still has the same two Aeneas-library axioms).

| Theorem (module) | Rust | Says |
| --- | --- | --- |
| `serve_paths`, `serve_upstream`, `serve_guest_reply` (`GarrettProxyController`) | `proxy_controller::serve` | For any native callbacks: nothing is sent unless the session is current and the admission audit ran; the bytes sent are exactly the encoder's output; the guest gets a fixed refusal or released bytes with no credential form. |
| `frame_paths` (same) | `proxy_controller::frame` | A request reaches `serve` only through the strict parser and within the raw bound. |
| `admit_open`, `authenticated_true`, `same_secret_true` (`GarrettProxyConnect`) | `proxy_connect::admit` | A tunnel opens only for the session token (constant-time compare), a configured origin and a live session. |
| `dropped_eq` (19 names), `bad_escape_at_spec` (`GarrettProxyHttp`) | `proxy_http` | Method-override and Range fields are dropped; equivalent path spellings are refused. |
| `unwrapped_spec`, `reflects_spec` (`GarrettProxyResponse`) | `proxy_http` | Reflection is also checked with line breaks removed (MIME-wrapped base64). |
| `fill_target_exact`, `fill_target_safe`, `scalar_text_*` (`GarrettRoute`) | `route` | Every named operation's provider target is exactly the template filled with the arguments' text, using only unreserved bytes and `/ ? = &`. |
| `parse_template_some`, `parse_piece_spec` (`GarrettRoute`) | `route::parse_template` | A parsed policy template writes back to exactly its text, and every piece is a valid segment or `{name}`. |
| `translate_round_trip`, `translate_exact` (`GarrettRouteMatch`) | `route_match::translate` | The guest-side translator accepts a target only if the host's own `fill_target` writes it back byte for byte. |
| `control_paths`, `manifest_description_exact` (`GarrettControl`) | `control::control` | `renounce` revokes, records, then deactivates; `describe` reveals only operation names and the write mode; neither reaches a provider. |
| `public_field_name_spec` (`GarrettPublicFieldNameContract`) | `selected_conversion::public_field_name` | Accepts exactly 1–32 bytes, lowercase first, `[A-Za-z0-9_]` throughout. |
| `parse_request_bounds` (`GarrettProxyParse`) | `proxy_http::parse_request` | An accepted request consumed no more than the buffer, and its decoded body (length or chunked) is within the limit. |

Assumption changes (ledger `docs/planning/aivm-secrets-assumptions.json`):

| ID | Before | Now |
| --- | --- | --- |
| `PROXY-NATIVE-01` | The whole native shell was trusted to sequence requests and write only core outputs | Only socket/TLS I/O, deadlines and the session clock; sequencing, admission and framing are proved |
| `ROUTE-NATIVE-01` (new) | Target construction and template parsing were native, implicitly trusted | Only the JSON layer (reading template strings and arguments) |
| `CONTROL-NATIVE-01` (new) | `describe`/`renounce` were unaccounted for | Only the three callbacks (revoke, audit append, grant flag) |

**Hypotheses that need your attention.** `serve_upstream` and
`serve_guest_reply` assume the encoding (or checked response) fits in a
`usize`; `parse_template_some` assumes the template is shorter than
`usize::MAX`; `scalar_text_integer` assumes a 64-bit `usize`. Both are memory or
platform bounds, not security premises. No theorem has a premise that
restates its conclusion; please check that claim against the statements.

## 3. Reading guide: one allowed and one refused request

Constrained profile, guest side (`tests/test_native_session.py`,
`test_constrained_proxy_reads_a_github_shaped_pull_request`):

1. `curl https://api.example.org/repos/owner/repo/pulls/N` in the guest
   connects to the guest's `garrett-proxy`. `proxy_connect::admit` opens the
   tunnel only for its session token (`admit_open`).
2. `proxy_controller::frame` hands the parsed request on (`frame_paths`).
3. `manifest::Policy::translate` asks `route_match::translate` for
   arguments; they are accepted only because `route::fill_target` writes the
   same target (`translate_round_trip`).
4. The guest client sends the named operation `pr.diff` to the host bridge,
   which authorizes it, runs its own `pull` check and the read, and releases
   only the disclosure (the native-read theorems in the tour's earlier
   sections). The provider target is written by `fill_target`
   (`fill_target_exact`).
5. A request for pull `N+1` fails step 3 (the route copy's allowed values),
   so no bridge call happens; with a tampered route copy it fails at the
   bridge (`tests/test_proxy_guest_translator.py`).
